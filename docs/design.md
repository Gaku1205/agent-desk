# agent-desk デザイン仕様

画面の見た目のルール。2026年11月15日に、それまでの「流れ × 誌面」（光の粒・極太の数字・画面全体の川）をやめ、**1カラムの会話形式**に作り直した（Issue #281。画面案は作らず、この文章で決めた）。挙動のルールは `docs/spec.md`。

## 方針

- 体験の核：**開くと、画面の真ん中に「今あなたが答えること」が1つだけある。** 質問・説明とボタン（と答えの欄）だけが最初の1画面に見え、片づけると次の1件に替わる。その下に、AIたちの進み具合が、会話のメッセージのように縦に流れる
- スマホ（幅899px以下）の画面は**読みやすい幅の1本の列**。左右に別の列を置かない。PC（幅900px以上）のホームとリポジトリのページだけは**3ペイン**（左：リポジトリの一覧／中央：あなたの番・いまの様子・下にIssueを追加する入力欄／右：進捗図の列。2026年11月15日、Issue #286 のオーナーの指示で変え、2026年11月16日、Issue #300 で進捗図を右の列の縦の図に移した。下の「PCの3ペイン」）。中央の「あなたの番」と「いまの様子」は1本の列で、左右の列の間を幅いっぱいに使う（2026年11月16日、Issue #347）。Issueを書く・ログイン・見つからないページは、PC でも1本の列。設定は左に目次・右に節の2列（2026年11月18日、Issue #507。下の「設定」）
- **余白と文字が中心**。色は最小（地・文字・薄い文字・強調の1色（インディゴ）と、GitHub と同じ状態の色（赤・黄土・緑・青・紫））。大きさ・太さ・行間・余白の差で、何が主役かを見せる。地味で無難な画面にしない（行間を詰めた小さい字の羅列、どこも同じ大きさの字にしない）
- 雰囲気の参考は Claude アプリの会話画面（コピーはしない）：無彩色の地（白と黒の2テーマ）に、読みやすい文字、広い行間
- **軽く**：光の粒・極太の数字・キャンバスの描画・すりガラス（`backdrop-filter`）・凝った動きは使わない。動きは切り替わりの短いフェードだけ。**例外は「いまの様子」のランプの緑の線だけ**：静かに脈打つ（明るさだけがゆっくり変わる。2026年11月16日、Issue #295 のオーナーの指示。下の「ランプ」）。ほかに、進行中を示す回る印（進捗図と「いまの様子」の動いている作業と、押したボタンの `〜中…`。下の「動き（まとめ）」）
- **避けること**：数字を大きく並べたタイル、同じ角丸・同じ影のカードの並び、ピル型バッジの多用、飾りのグラデーション、絵文字、太い枠・硬い黒線、見出し上の字間を空けた英大文字、光る点・にじみ（**「いまの様子」のランプの、脈打つ緑の線だけは例外**。光（影・にじみ）は付けない）、標準のフォーム部品をそのまま枠に並べた物、塗りつぶしのインディゴを「オン」などの状態に流用すること
- 状態は色だけで伝えない。「あなたの番」は種類の札と説明文、会話は話し手と文を持つ
- **塗りの色は、ほんとうに急ぐ所だけ**：色つきの塗りのボタンは Fix（止まった・公開失敗）の赤だけ（とログインの入口のインディゴ）。ほかの1件の主役のボタンは文字色（`--bone`）の塗り。種類の色は札の文字・記号・縦線に使い、塗りには使わない（「あなたの番の種類と色」）
- **キーボード**：Tab で回る数を少なく保つ。最初に届くのは「あなたの番」の1件のボタン
  - フォーカスの見える位置：入力欄（Issueを追加する欄）のあるページ（ホーム・リポジトリ）では、フォーカスが当たった物は、上の帯と下の入力欄の間に見える位置までスクロールされる（上は帯の高さ＋8px、下は入力欄の高さ＋8px の余白。入力欄の高さは測って `--composer-h` に入れる）。入力欄の無いページには効かせない。新しい色・寸法は増やさない
- リンク：アプリの中のページ（`/` で始まるURL）は同じタブで開く。外のサイト（`https://`）だけ新しいタブで開く
- 文言は人の言葉で短く。会話の文は「〇〇が△△しています」のように、声に出して読める日本語にする（頭に「いま」は付けない。動いていることは回る印で分かる。2026年11月16日、Issue #347）。日本語の文は「、」「。」で分けた塊ごとに折る（文節の途中で切らない）
- **文言のそろえ方**（2026年11月19日、Issue #553）：
  - **見出し・短いラベルは英語**。見出しの横の日本語の補足は、**意味を足すときだけ**1つ、短く。数は見出しの横に数字だけ（`Your turn 1`・`Activity 9`・`Queue 14`）
  - **説明の文・ボタン・エラーは日本語**。「物」「処理」「枠」のような何でも指せる言葉を避け、何がどうなっているかを書く
  - 同じ物は同じ言葉：日本語の文の中では `席`（`枠` は使わない）、`作業`（`処理` は使わない）、`順番待ち`。英語のラベルは `Slots`・`Queue`・`Running`・`Free`。人間の判断待ちは、画面では全部 `Your turn`（`あなたの番` は画面に出さない。この文書の節の名前としては「あなたの番」と書いてよい）。進行中の作業の会話は、画面では `Activity`（節の名前は「いまの様子」のまま）
  - 時刻と上限の書き方は「今どうか → 次にいつ変わるか」の順（「Slots & Queue」の見出しの下の1行）
- **英語にしてよい言葉（画面全体で使う物）**：`Your turn`・`Activity`・`Repositories`・`AI`・`Fix`・`Answer`・`Ship`・`Start`。各ページだけで使う物は、そのページの節の「英語にしてよい言葉」（設定・Dashboard・Slots & Queue・導入）

## 色

白と黒の2テーマ。強調（見出し・リンクなど）は**インディゴ1色**。状態の色は **GitHub の Primer と同じ色使い**：danger（赤）・attention（黄土）・success（緑）・accent（青）・done（紫）。それ以外は無彩色（グラデーション・影・光る装飾は使わない）。2026年11月15日、Issue #287 のオーナーの指示で、それまでの「ダークのみ・強調はアンバー」から変え、2026年11月18日、Issue #459 のオーナーの指示（「github と同じ色使いに」）で、状態の色を GitHub に合わせた。

CSSカスタムプロパティとして `globals.css` に定義し、コードではこの名前だけを使う。名前はどちらのテーマでも同じで、値だけが替わる。

- **順番待ちは紫**：「いまの様子」のランプの順番待ちの線と `· ⧗ 2` の字、順番待ちの印（砂時計）、順番待ちのまとまりの見出しの字、**CI の枠待ち**（Actions の席が空かず、チェックがまだ始まっていない `queued`。Slots の席の行の CI の割合の線と `⧗6` の数。Issue #583）だけ `--wait`（白 `#8250DF`・黒 `#AB7DF8`。GitHub の done と同じ紫。地との比：白 4.8:1、黒 6.5:1 以上）。ほかの所では使わない（2026年11月16日、Issue #295。値は Issue #459 で GitHub に合わせた）。CI の枠待ち・実行中に GitHub の黄色（pending）は使わない（黄土 `--attention` は Answer 専用）

- **色だけで意味を伝えない**。「あなたの番」の種類は、色に必ず英語の名前と記号を併せて出す（札の文言と記号）。インディゴ＝「あなたの番」の見出しの文言、緑＝チェックの形、赤＝×の形・`公開に失敗` などの文言を、必ず併せて出す
- **選び方**（挙動は `docs/spec.md` の「テーマ」）：`<html data-theme="light">`（白）・`"dark"`（黒）。付いていないとき（OSに合わせる）は `prefers-color-scheme` で決める。`color-scheme` も合わせる（標準のスクロールバーなどが追従する）
- 色の直書きが許されるのは次だけ：`globals.css` の変数の値、`mask-image` の `#000`（色ではなく透け具合）、`layout.tsx` の `Viewport.themeColor`（ブラウザの外枠の色なのでCSS変数が使えない。ライトもダークも藍 `#4f46e5` の1色。「アプリのアイコン」。2026年11月19日、Issue #552）、アプリのアイコンの絵の色（`src/app/icon.svg`・`src/lib/appIcon.tsx`）、`src/lib/demo/` のサンプルのデータの色の見本（画面の色ではなく、見た目の方向という「中身」）
- 仮に決めた所（画面案なし）：白・黒の各値（インディゴは `#4F46E5` / `#818CF8`、地は `#FAFAFA` / `#121212` を基準に）、緑、縁・下地の不透明度、後ろの幕の濃さ

## 文字

- 和文：`IBM Plex Sans JP`（400 / 500 / 700）。欧文・数字：`Geist`（可変）。ワードマーク：`Bricolage Grotesque` 800（`font-variation-settings: "opsz" 96`）
- 3つとも `next/font/google` で読む（`src/app/layout.tsx`。変数は `--font-jp`・`--font-latin`・`--font-disp`）。本文の指定は `--jp`（Geist → IBM Plex Sans JP の順）
- 和文のフォントは先読みしない（`preload: false`。2026年11月19日）：日本語のフォントは細かく分かれたファイルで配られ、先読みすると、そのページで使わない分まで全部（woff2 247個・2.8MB）を開くたびに読みに行き、最初の描画が遅れていた。先読みしなければ、画面の文字に要る分だけが読まれ、読めるまでは代わりの字（`system-ui`）で先に出る（`display: "swap"`。読めたら入れ替わる）。欧文の2つ（Geist・Bricolage Grotesque）は今までどおり先読みする（ファイルが1つずつで小さい）
- 等幅フォントは使わない。番号・時刻・件数は Geist の `tabular-nums`（`.num`）で桁をそろえる。例外は導入（`/setup`）の、打つコマンドの1行（`claude setup-token`）だけ（`ui-monospace, SFMono-Regular, Menlo, monospace`。Issue #517）
- 大きさの段（PC／スマホ）：
  - 「あなたの番」の題名 30px／21px（700、行の高さ1.4、字間 −0.01em、`text-wrap: balance`）
  - 「あなたの番」の説明文 17.5px／15.5px（行の高さ1.8）
  - 会話の文 16px／15.5px（行の高さ1.75）
  - 小見出し・札・ボタン 13〜14.5px、補足 12.5〜13px
- 日本語は詰まって見えるので、11.5px より小さい文字は使わない
- 文字の色は、地に対して 4.5:1 以上になる物だけを使う（`--bone`・`--bone-2`・`--mute`・各 `-soft`。不透明度を下げて薄くした文字は作らない）
- 本文は `font-feature-settings: "palt"`（かなを詰める）
- **改行**：`word-break: auto-phrase`（文節の途中で切らない）。説明文は「、」「。」のあとで `span.ph` に分け、塊ごとに折る（`src/lib/turnKind.ts` の `splitPhrases`）。折り返さない物（`white-space: nowrap`）：番号、時刻・待ち時間、ボタンの文字、足あとの1つ1つ

## 操作が届かなかったときの知らせ

サーバーの操作の呼び出しそのものが失敗したとき（`docs/spec.md` の「操作」）の文言。見た目（色・文字・位置）は、その場所の今のエラーの表示（「あなたの番」の1件の理由、Issueを作る欄の理由、設定の保存の理由）と同じで、足すのは文言だけ。

- `サーバーに届きません。読み込み直してください`

同期（上のバーの右端）が届かなかったとき（呼び出しが失敗した・30秒たっても取り直しの結果が届かなかった）も、同じ文を出す。同期には本文の欄が無いので、回数制限の知らせと同じ場所――同期の `title` と、更新ボタンの読み上げ（`更新（最後に取り直した時刻 HH:MM:SS）。サーバーに届きません。読み込み直してください`）――に出す。見た目（点の色・文字）は変えない。同期の時刻は最後に取り直せた時刻のまま。次に取り直せたら消える。止めている理由（回数制限）と重なるときは、この文を先に出す。
